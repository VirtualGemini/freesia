# Freesia Web

<img src="./public/brand/freesia-mark.svg" width="64" height="64" alt="Freesia" />

[English](./README.md) | 简体中文

Freesia Admin 的 Web 界面，使用 Vue 3、TypeScript、Vite、Element Plus 和 Pinia。

## 本地开发

需要 Node 20.19+ 和 pnpm 11。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

访问 `http://localhost:3000`。开发环境将 `/api` 转发到 `http://localhost:8080`，可通过 `VITE_API_PROXY_URL` 指定其他后端。密码登录和当前端退出已接真实后端，首位管理员初始化见根 README；其余管理能力逐步接通。

登录滑块只保留本地交互，不是服务端防刷；不持久化密码或请求后端验证码票据。Access 只在内存，不进入浏览器存储；Refresh 使用持久化 HttpOnly Cookie，不出现在响应 JSON 或 JS 可读凭据中。刷新／重开浏览器只恢复经服务器验证的会话，并重新查询账号、菜单和权限。

只有明确 Access 过期才刷新并续接尚未执行的原请求一次，同页并发共享刷新。网络／503 故障和刷新响应不明保留页面与会话，不自动重放业务。退出同步到同浏览器其他标签；同账号重登重查权限后恢复工作标签，换账号清空。既有工作台内容仍是演示。

菜单维护后在当前会话刷新账号可使用的导航，无须整页重载。已缓存 iframe 菜单清空外链后恢复内部页，不在其上方残留空白 iframe。路径不再注册的工作标签会清理，固定标签也不例外；404 兜底不代表旧标签仍有效。仅隐藏但仍可使用的页面继续保留。

登录、刷新和退出通过同源 `/api` 代理发送 `X-Freesia-CSRF: 1`。生产须使用 HTTPS 与 Secure Cookie，不要通过开放跨来源携带凭据访问绕过同源边界。

浏览器须支持安全上下文中的 Web Locks（HTTPS，本地开发可用回环 HTTP）；只有认证变更共享跨标签锁，Access 更新通过临时 BroadcastChannel 消息传递，不通过存储事件传递凭据。

## 配置

- `VITE_BASE_URL`：部署路径，默认为 `/`。
- `VITE_API_URL`：API 来源地址，生产环境留空时使用同源请求。
- `src/config/product.ts`：产品名称、描述、标志与链接。

## 验证与构建

```sh
pnpm lint
pnpm typecheck
pnpm build
```

构建产物输出到 `dist/`，使用 `pnpm serve` 在本地预览。

### 导航刷新回归

使用生产构建，在同一浏览器会话内操作专用测试菜单，并保留测试数据：

1. 打开已启用缓存的 iframe 菜单，通过应用内“菜单管理”Tab 返回，将外链 A 改为 B 后再次打开，确认 iframe 实际加载 B。
2. 仍通过该 Tab 返回，保留内部组件、清空外链，保存后再次打开。不刷新浏览器，确认内部页从首屏开始且没有空白 iframe；重复一次 iframe 到内部页的切换。
3. 打开另一菜单，返回维护页将其停用，确认导航入口和对应 Tab 同时消失，其他可用 Tab 保留。固定 Tab 也重复验证，最后恢复测试菜单启用。
4. 修改已打开菜单的路径但保留路由名，确认旧路径 Tab 清理、新入口可用，最后恢复测试路径。
5. 仅隐藏已启用菜单、不撤销使用权限，确认导航入口消失，但已有 Tab 和手工路由仍可使用。

步骤 1–5 全程使用应用内导航：整页刷新会销毁旧缓存，可能掩盖刷新缺陷。最后可另行刷新核对持久化值，不能替代上述验证。

### 角色删除回归

使用 Computer Use 在隔离测试环境中操作真实浏览器。通过既有角色表格打开单删／批删，核对角色名称／编码、只读可见账号及昵称，确认只有指定文案与角色名称／编码／授权账号三列；取消后角色／绑定不变。确认后核对列表最新结果和批选清理。在预览与确认之间改变绑定或撤销操作权限，核对拒绝文案、不可继续确认、须显式重新预览，且不伪报成功。检查中英文及窄屏。预览失败不能降级为普通删除确认；真实浏览器的破坏性操作须在执行时确认。

### 账号生命周期回归

使用实际 test Compose 和真实浏览器 Computer Use，以独立测试账号通过 **编辑账号 → 账号设置 → 账号状态 → 保存** 修改单个账号状态，直接保存状态，不弹状态确认框；操作列不另加启停图标。启用／异常使用启用权限，停用使用停用权限，搜索与展示同步保留三态且不再提供注销，初始化唯一超管的状态只读。资料、组织、角色和状态仍是独立请求，后续请求失败时抽屉说明此前变更可能已保存，不声称整体原子成功。

验证无 spinner 的原样按钮与稳定表单、单条启用账号仅 toast、单条停用账号确认后删除、超管隐藏删除且禁选、批量停用／删除的账号表格、含启用目标的批量删除拒绝名单、仅停用可删名单预览、取消、非法批次拒绝、变化后重新预览、列表刷新与选择清理，并检查中英文及窄屏。另一个设备保持登录：停用后下次请求／刷新必须拒绝，重新启用不能恢复旧凭证。保留既有数据，仅使用独立 QA 账号执行破坏性测试。503 或结果不明时保留页面并展示错误，不伪报完成；已撤销会话可能须重新登录。未接通的安全／恢复控件不属于本能力。

账号／角色确认沿用原 MessageBox 外观与过渡。单条账号删除不带表格；账号批量停用／删除、角色单量／批量删除展示按内容排版的表格，不显示黄色警告图标。确认框最大宽1280px、表格最大高600px，并随可用视口收缩。长表头和内容换行，短表不预留固定高度，长表在表内滚动。检查宽内容不会引入页面最右侧的多余滚动条，且表内仍可滚动到最后一行。
